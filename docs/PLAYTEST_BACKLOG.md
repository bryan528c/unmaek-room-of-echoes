## UPGRADE-04 완료 범위

- 정의와 Run 상태 분리: 카드 수치는 `baseValues`, 보유 중첩·발동·기여량은 `UpgradeSystem`이 관리한다.
- 활성 카드 18장 중 행동 변화형 17장(94.4%). 기존 구조와 충돌하는 15장은 기록 호환성을 유지한 채 선택 풀에서 제외했다.
- 잔향 칼날 / 절단·패링 / 언령 / 생존·범용 카테고리와 태그 가중 선택을 적용했다.
- 첫 보상은 무기·절단, 패링·언령, 생존 카드가 각 1장씩 나오며, 이후에는 보유 태그·공명 완성 후보를 우선한다.
- 카드별 발동 횟수, 피해·회복·문장력·쿨다운 감소·생성 개체를 Run 통계에 기록한다.
- 월환 공명, 시간 역조, 반격 절문, 회귀 사슬을 두 카드 자동 조합으로 활성화한다.
- 카드 선택 화면에 현재 → 선택 후 수치, 중첩 방식, 태그, 공명 가능 여부를 표시한다.
- HUD에는 카드 아이콘·중첩·최근 발동·공명을 간결하게 표시하고, 일시정지·결과 상세에서 전체 기여량을 제공한다.
- F4 개발 메뉴에 세 빌드 및 네 공명 검증 프리셋과 기여 통계 초기화를 추가했다.
- 전체 카드 감사 결과는 [UPGRADE_AUDIT.md](./UPGRADE_AUDIT.md)에 기록한다.

## UPGRADE-04R / 04R2 — 완료

- 카드와 공명의 발동, 피해, 회복, 문장력, 쿨다운 감소, 반사 탄환, 영향 대상, 방지 피해, 조건 실패를 같은 기여 스키마로 기록한다.
- 발동 시점과 후속 적중을 분리해 다단 효과가 발동 횟수를 부풀리지 않도록 한다.
- 결과 화면에 활성 공명, 기여 상위 3개, 피해 원천 비율, 전체 카드·공명 기여량과 미발동 카드까지 표시한다.
- 회귀 잔상은 기록된 방향을 유지하면서 유효한 연결 대상을 우선하고, 정지 역류는 탄환당 1회·공명당 3개 상한을 유지한다.
- 직전 미선택 카드의 다음 보상 재등장을 차단하고 HP·보유 태그·공명 완성·제시 빈도를 선택 점수에 반영한다.
- 카드 선택 500 Run 시뮬레이션과 세 빌드 60초 고정 입력 비교를 개발 검증 경로로 유지한다.
- `RunProgressController`에서 Run 범위 카드·공명·기여 통계와 Act 범위 Wave·테마·세대 상태를 분리한다.
- 기본 피해 원천은 잔향 칼날 / J 절단 / 패링 / 언령 / 기타로 배타 집계하고, 카드·공명 피해는 중복 가능한 추가 기여 축으로 표시한다.
- 문장 과충전은 F 대기 후 Q/E/R이 피해·상태·회복·지속 효과 중 하나를 실제 적용한 경우에만 발동하며, 실패 사유를 통계에 남긴다.
- 멎는다 이후 E 슬롯에 정지 탄환 수와 역류 가능 시간 또는 최소 파동 fallback을 표시한다.

## RUN-ACT-05 — 완료

- `RunActDirector`가 Run의 Act 번호, 보스 처치, Act별 기록과 actId 세대를 관리하고 기존 `RunProgressController`는 카드·공명 Run 상태를 유지한다.
- Act 1 보스 처치 후 결과 화면 대신 행동 변화형 보스 보상과 3초 Act 전환을 거쳐 Act 2로 이어진다.
- Act 2 `먹빛 기록고`는 별도 절차적 배경, 먹물 잔향탄, 봉합 쌍, 과거 위치 공격, 혼합 Elite Wave를 사용한다.
- Act 2 보스 `기록 편집자`는 교정 / 삭제 / 재편 3단계로 패링, 되돌린다, 잇는다·멎는다·절단을 시험한다.
- Act 3 이후는 두 테마와 보스를 변주하고 1~2개 Modifier, 상한이 있는 체력·피해 배율로 반복한다.
- 보스 클리어는 Run을 종료하지 않으며 플레이어 사망 또는 명시적 Run 포기 때만 결과를 정확히 한 번 연다.
- Act 전환 시 적·보스·탄환·Telegraph·상태 UI·Tween·Timer를 정리하고 runId와 actId가 다른 지연 콜백을 차단한다.
- 가속된 20분/5 Act 수명 주기 시뮬레이션으로 조기 Result, stale callback 수락, Timer·Listener 증가를 검증한다.

## RUN-ACT-05R — 완료

- 보스 종료 흐름을 `BOSS_DEFEATED → ACT_CLEAR → BOSS_REWARD_REVEAL → BOSS_REWARD_SELECT → ACT_TRANSITION → ACT_INTRO → WAVE_COMBAT`으로 분리하고, 모든 전환을 `GameFlowController`가 검증한다.
- 보스 단계마다 독립 체력, 대표 패턴 실행 여부, 전환 잠금을 두어 초과 피해가 다음 단계로 넘어가거나 한 프레임에 여러 단계가 생략되지 않게 한다.
- 기록 포식자와 기록 편집자는 별도 `BossDefinition`을 사용한다. 기록 편집자는 교정·삭제·재편 단계와 기록판·교정선·펜촉 실루엣을 사용한다.
- Act 2의 봉합 쌍·과거 교정·편집 실험은 최초 상세 안내와 재등장 축약 안내를 사용하며, 안내 중 전투 입력과 적 생성은 잠근다.
- 보스 보상은 일반 Wave 보상과 다른 제목·테두리를 사용하고, Act 완료 화면·회복·보상·다음 Act 소개가 순서대로 진행된다.
- HUD는 핵심 카드 5개와 `+N`, Act·Wave·Modifier·처치 보스를 표시하며 F 준비 완료는 효과음·점멸·비문 고리·1회 안내로 알린다.
- 브라우저에서 Act 1과 Act 2의 모든 보스 단계, Act 3 진입, 가속 진행을 통한 Act 5 도달, 사망 결과 1회, 새 Run 초기화를 확인했다.
- 결정론적 20분/5 Act 수명 주기 테스트로 조기 Result, 단계 생략, 오래된 콜백 수락과 상태 누적을 회귀 검증한다.

## 유지하는 확정 방향

- 키보드 전용 기본 조작과 빠른 재시작을 유지한다.
- 잔향 칼날은 약한 자동 보조 피해이며 자동 승리 수단이 아니다.
- J 절단은 자동 추적·강제 이동 없는 8방향 수동 공격이다.
- 패링은 플레이어 Hurtbox 중심의 360도 타이밍 판정이다.
- Q/E/R 세 언령과 기존 세 연계는 다음 언령 확장 전에 완성도를 우선한다.
- 카드·공명은 Run 범위 상태이며 새 Run에서 모두 초기화된다.

## RUN-ACT-05R2 — 완료

- 동기식 파생 피해 재진입을 중앙 `DamageQueue`의 반복 처리로 교체했다. 모든 이벤트는 root/parent/event ID, runId/actId, 원천·카드·공명·플래그와 처리 handler를 보존한다.
- 파생 깊이 6, 루트당 파생 64, 프레임당 256 이벤트 상한을 적용했으며, 초과 이벤트만 차단하고 게임 루프는 계속 진행한다.
- 기록 포식자 제3형의 연결·공유·카드 파생 피해 회귀를 1,000 루트 이벤트로 고정 재현하고 30회 연속 자동 검증했다.
- HITSTOP은 실시간 타이머와 120ms 누적 상한을 유지하며 USER_PAUSE, TAB_HIDDEN, 전환 토큰과 독립적으로 해제된다.
- Act 2 적의 전체 footprint와 대형 Telegraph를 안전 경계 안으로 보정하고, 높은 위험·추적·Modifier 공격을 `ThreatBudget`으로 분산했다.
- 편집 실험은 두 Modifier 빈도 75%, 피해 88%, 시작 안전 시간 2.6초를 사용한다.
- 최근 3개 플레이어 피해와 최종 공격자·패턴·Modifier·피해·패링 가능 여부를 Run 결과에 보존한다.
- 튜토리얼과 Modifier 최초 상세 안내는 저장하며 새 Run에서는 아직 보지 않은 안내만 노출한다.
- 기록 편집자 3단계, 보스 보상, Act 3 진입과 개발용 Act 5 진입을 브라우저에서 확인했다. 자동 장기 진행은 최소 Act 5와 20분 수명 주기를 검증한다.

## RUN-ACT-05R3 — 진행 중

- Endless Act 제목에서 중복 Act 숫자를 제거하고 사용자 화면의 Modifier·적·공격 이름을 한국어 표시명으로 분리했다.
- Act 3 Wave 1은 첫 Modifier만, Wave 2 이후는 두 Modifier를 사용하며 보상 이후 1.25초 안전 시간을 유지한다.
- 추적자 돌진은 일반 Act 3에서 동시 준비 1개와 시작 간격 720ms를 적용하고, 높은 위험 공격 예산을 공유한다.
- 기록 포식자 제3형은 최소 4.2초와 대표 패턴 실행을 모두 충족해야 단계 종료가 확정된다.
- 결과의 기본 J 절단 피해는 낮은 직접 피해만 집계하고 STOPPED·LINKED·MARKED·DISPLACED 반응은 별도 반응 축에 기록한다.
- 기존 세 연계와 신규 반응은 호환 슬롯, 반응명, 남은 시간, 대상·상태 문맥과 결과 설명을 HUD에 표시한다.
